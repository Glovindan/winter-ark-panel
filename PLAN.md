# Winter Arc Panel — план

## Решения
- Платформа: Telegram Mini App (вход через подпись `initData`), бот присылает вечерний опрос.
- Стек: TypeScript, Fastify/Hono, React + Vite, SQLite, grammY. Один процесс, VPS.
- Арка: 19.10.2026 (пн) — 28.02.2027 (вс), 133 дня = 19 полных недель. Конец можно поменять в `arc`. Один часовой пояс на всю арку (по умолчанию Москва).
- Фиксированные пункты (нельзя убрать): Питание (галочка «уложился в КБЖУ»), Тренировка, Сон.
- Личные пункты: каждый добавляет/удаляет свои. Видны только самому участнику и в детальной странице участника; в кольца и общий % не входят.
- Личные значения: норма КБЖУ, норма сна, **число тренировок в неделю**, время вечернего опроса (выбирает сам).
- Правка задним числом: только сегодня и вчера.
- Админ: один, tg_id в конфиге. Участники заходят по ссылке-приглашению через бота.

## Логика колец (по одному на фиксированный пункт)
- Питание, Сон: каждый день арки = 1 слот. Отмечен → выполнено; день закрыт без отметки → пропущено; будущие дни → серый.
- Тренировка: неделя (пн–вс) даёт N слотов (N — цель пользователя). Выполнено = min(отметок за неделю, N). Пропущено = N − выполнено, но только когда неделя закрыта. Текущая неделя в пропуски не идёт.
- Закрытие дня: cron после полуночи по часовому поясу арки.

## Модель данных (SQLite)
| Таблица | Поля |
|---|---|
| arc | start_date, end_date, tz |
| user | tg_id, name, avatar_url, kcal/protein/fat/carb (справочно), sleep_hours, workouts_per_week, poll_time |
| habit | id, kind (nutrition/workout/sleep/custom), owner_id (null для фиксированных), title |
| checkin | user_id, habit_id, date, status (done/skipped), updated_at |

## API
- `POST /auth` — проверка initData, сессия
- `GET /dashboard` — агрегаты колец по всем участникам
- `GET /users/:id/days` — детали по дням (включая личные пункты)
- `PUT /checkin` — отметка (сегодня/вчера)
- `GET/PUT /me` — профиль и личные значения
- `CRUD /habits` — личные пункты

## Структура репозитория
```
apps/web        React + Vite (Mini App)
apps/server     API + бот + cron
packages/shared типы и правила подсчёта
```

## Этапы
1. Каркас: monorepo, БД, миграции, авторизация initData.
2. Экран «Сегодня», профиль, личные пункты.
3. Дашборд с кольцами и детали участника.
4. Бот: приглашения, вечерний опрос с inline-кнопками, закрытие дня.
5. Деплой (VPS + HTTPS), тёмная/светлая тема, бэкап SQLite.

## Статус
- Этапы 1–4 сделаны. Осталось: этап 5 (деплой, HTTPS, тема, бэкап SQLite).
- Пропуски считаются на лету (день раньше «сегодня» без отметки = пропуск), отдельное закрытие дней cron не нужно.
- Приглашения: один общий код в таблице `setting`; админ получает ссылку командой /invite, /newinvite отзывает старую.
- Бот: long polling, запускается при BOT_ENABLED=1; вечерний опрос шлётся в личное время (окно 2 часа, раз в сутки).
